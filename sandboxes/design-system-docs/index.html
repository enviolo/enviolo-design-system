Principles

One job per view

Each screen has one primary action. If two feel equally important, split the screen.

Pills act, corners hold

Based on the Luma style of shadcn/ui: controls are pill-shaped, while cards, panels and dialogs keep soft corners. Shape tells people what they can press.

Tokens, not values

Components only use semantic tokens, and states like hover are token fills, never opacity tricks or colour mixes. Change a ramp or a mode and every screen follows.

Warm days, cool nights

Light mode runs on Taupe, dark mode on Mist. The brand ramp moves like the sky, from sunset to midnight.

How the system is built

Three layers. Each layer only changes what sits below it, never how it's named.

Enviolo tokensBrand layer, on top

The values that make it Enviolo: the colour ramp, Taupe and Mist neutrals, status colours, accent and focus, Source Sans 3 and Tabler icons. It sets values and never renames anything, so every library underneath keeps working.

Enviolo CSSBackbone for the web, modelled on Basecoat

Our own stylesheet, modelled on Basecoat: the same components as plain HTML, a base class plus attributes, for websites and CMS templates. No React and no third-party library needed.

Figma mirrors the same variables through the shadcncraft kit. For AI-assisted development, design.md describes all three layers, so Claude or Cursor picks the right backbone for each surface and only uses Enviolo tokens. A component the web stylesheet doesn't have yet is not part of the system until it is added.

About this page

Plain HTML, CSS and a little vanilla JavaScript, with no framework and no build step. No component library is loaded. Buttons, inputs and status pills come from tokens/components.css, the same stylesheet websites use; the rest of this page's CSS is documentation only.

Markup is a base class plus attributes (class="btn" data-variant="secondary"), the same split shadcn/ui makes with <Button variant="secondary">. Colour and radius tokens use shadcn/ui naming (--primary, --secondary, --muted, --border), so the same tokens drop into a React shadcn setup or a Figma variables file. The visual style is based on Luma, which brings the pill-shaped controls. Enviolo-specific choices on top: a two-ramp neutral system for light and dark, and the Enviolo colour ramp.

New components start from Basecoat as a reference, then get ported into our own stylesheet and checked in both modes, so every state follows the same rules.

Buttons

Four types cover almost every action: primary, secondary, outline and ghost. Each has one job, and together they show people what matters most on a screen.

The four types

Ranked by emphasis. Secondary and outline share rank 2; the surface they sit on decides which one to use.

Primary

Rank 1
btnvariant="default"

Use for the main job of the view, like Find a dealer, Place order or Start course.

Avoid more than one per view. If two actions feel equally important, the view is doing two jobs.

Secondary

Rank 2
data-variant="secondary"variant="secondary"

Use for supporting actions on plain backgrounds, filters and toggles, and a second action with a consequence.

Avoid cards, dialogs and imagery, where the muted fill blends into the surface.

Outline

Rank 2
data-variant="outline"variant="outline"

Use for supporting actions on cards, panels, dialogs and imagery, and the safe way out of a dialog.

Avoid full-width buttons in mobile forms, where a bordered pill reads like an empty input.

Ghost

Rank 3
data-variant="ghost"variant="ghost"

Use for repeated actions on rows and toolbars, skip or defer actions, and icon buttons.

Avoid the only action on a screen, or anything people must not miss.

Also available

Two special-purpose variants outside the ranking.

Read the warranty terms

Link

Inline
data-variant="link"variant="link"

Use for navigation inside a sentence.

Avoid standalone actions. If it does something, it should be a button.

Destructive

Special
data-variant="destructive"variant="destructive"

Use for irreversible actions, always next to an outline way out.

Avoid anything that can be undone, or as the default focus.

Choosing a type

Ask in this order and stop at the first yes.

  1. Is it the main thing people come here to do?Primary. Only one per view.
  2. Does it support the main job and change something?Secondary on plain backgrounds, outline on cards, dialogs and imagery.
  3. Is it repeated, optional or a way out?Ghost.
  4. Is it navigation inside a sentence?Link. Irreversible instead? Destructive, next to an outline way out.

Rules of thumb

One primary per view

If two actions feel equally important, the view is doing two jobs. Split it.

Primary goes last

Right-aligned on desktop footers, top of the stack on mobile.

Surface picks rank 2

Secondary on plain backgrounds, outline on cards, dialogs and imagery. Never both in one group.

Repeated means ghost

Anything shown on every row, card or toolbar slot drops to ghost.

Name the outcome

"Place order", "Download manual", not "Submit" or "OK". Icon-only buttons always get a label for screen readers.

Destructive is its own variant

Only for irreversible actions, and always next to an outline way out.

Colour

Two systems. Neutrals carry the interface; the Enviolo ramp carries the brand. Brand colours never go on buttons, text or borders.

Light to dark, like the sky: warm at sunset, cold at midnight. Use it for gradients, chart bars and volumetric effects. Select a swatch to copy its hex.

Rules

Sentence case

Headings, buttons and labels. No all-caps eyebrows.

Readable lines

Body copy stays under about 62 characters per line.

Mono for code only

Token names, hex values and code. Tables and numbers use the sans with tabular figures.

No word highlights

Don't colour or italicise single words in headlines. Hierarchy comes from size and weight.
